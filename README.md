# namaz-data

Официальные расписания намазов для приложения **Namaz Zaman**.

Данные собираются автоматически (GitHub Actions) из официальных источников
и публикуются как статические JSON. Приложение использует их с приоритетом над
собственным астрономическим расчётом.

- `update.yml` — ежедневно в 21:07 и 02:37 UTC (00:07 и 05:37 МСК), все источники;
- `districts.yml` — по воскресеньям в 04:00 UTC, дополнительно все районы Турции.

«Сегодня» во всех скриптах считается по UTC.

## Структура

```
index.json                                  — список городов с таблицами
timetables/<страна>/<город>/<YYYY-MM>.json  — помесячные расписания
scripts/build_all.py                        — оркестратор: все источники → index.json
scripts/parse_umma.py, parse_islamdag.py,
        parse_jakim.py, parse_muftiyatkg.py,
        parse_diyanet.py                    — парсеры сайтов и API
scripts/local_authorities.py                — SA, QA, OM (потоки ведомств); AE, KW, BH, EG, AZ, GB (расчёт)
scripts/official_feeds.py                   — KZ (muftyat.kz), UZ (fatvo.uz), Казань (dumrt.ru)
scripts/regional_feeds.py                   — BA/RS/ME (vaktija.ba), SG (MUIS), BG (grandmufti.bg)
scripts/dumkbr.py                           — КБР (годовая таблица ДУМ КБР)
scripts/calc_engine.py                      — резервный расчёт по методикам ведомств
scripts/audit_timetables.py                 — аудит данных против астрономии
scripts/compat/                             — совместимость с вышедшими версиями приложения
scripts/verify_live.py                      — ручная сверка сохранённого с живыми источниками
scripts/tests/                              — юнит-тесты скриптов
```

## Схема файла месяца

```json
{
  "city": "Нальчик",
  "slug": "ru/nalchik",
  "country": "RU",
  "lat": 43.4846, "lon": 43.6071,
  "timezone": "Europe/Moscow",
  "madhab": "hanafi",
  "source": "kbrdum.ru (Духовное управление мусульман КБР — официальная таблица по республике)",
  "source_url": "https://kbrdum.ru",
  "updated": "2026-09-13T19:26:57Z",
  "year": 2026, "month": 9,
  "days": [
    { "date": "2026-09-01", "fajr": "03:59", "sunrise": "05:29",
      "dhuhr": "12:16", "asr": "15:54", "maghrib": "18:44", "isha": "20:28" }
  ]
}
```

Время — `H:MM` или `HH:MM`, часы 0–23, минуты 00–59, только ASCII-цифры.
Приложение читает только `slug` и `days`; `updated` клиенты не используют, поэтому
файл переписывается, только если изменилось что-то кроме него.

Запись `index.json`: `slug`, `name`, `country`, `lat`, `lon`, `timezone`, `madhab`
(`hanafi` | `shafi`), `source` — обязательные (приложение декодирует индекс целиком),
`kind` (`official` | `calculated`) — у новых источников.

## Проверки перед публикацией

Workflow публикует данные, только если проходят:

- `scripts/audit_timetables.py` — формат и порядок времён, восход / Зухр / Магриб
  каждого дня против астрономии (ERROR при расхождении больше 25 мин), углы Фаджра и
  Иши против соседних дней (WARN), наличие данных на сегодня;
- `scripts/compat/check_schema.py` и `check_app_decoding.swift` — данные декодируются
  структурами вышедших версий приложения.

Город без данных на сегодня или с битой записью `build_all.py` убирает из индекса и
отмечает как сбой: job становится красным, но остальные города публикуются. С 15
декабря отсутствие таблиц ДУМ КБР и ДУМ РТ на следующий год — тоже сбой (ранний алерт).

Юнит-тесты: `python3 -m unittest discover -s scripts/tests`.
